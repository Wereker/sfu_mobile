# SFU — Мобильное приложение ИКИТ СФУ

Мобильное приложение для студентов и преподавателей кафедры «Систем искусственного интеллекта» Института компьютерных информационных технологий Сибирского федерального университета.

Приложение позволяет просматривать расписание занятий, следить за объявлениями и событиями кафедры, отмечать посещаемость через QR-коды и управлять своим профилем. Поддерживаются роли студента, преподавателя и администратора с разным набором доступных функций.

## Авторизация

![Авторизация](screenshots/auth.png)

Вход в приложение выполняется по email и паролю через REST API. После успешной авторизации access- и refresh-токены сохраняются в защищённом хранилище (`FlutterSecureStorage`).

При каждом запросе к защищённым эндпоинтам Dio-интерцептор автоматически добавляет заголовок `Authorization: Bearer <token>`. Если сервер возвращает 401, интерцептор пытается обновить токен через `/auth/refresh`. При неудаче токены очищаются и пользователь перенаправляется на экран входа без каких-либо дополнительных действий с его стороны.

## Главный экран

![Главный экран](screenshots/home.png)

Главный экран собирает ключевую информацию в одном месте:

- Карточка ближайшей или текущей пары с автообновлением каждые 30 секунд. Показывает статус: «Идёт N минут», «Начнётся через N минут», «Сегодня пар нет», «На сегодня всё». Первая пара дня показывается только если до неё осталось менее 90 минут.
- Информационные карточки с количеством актуальных объявлений и предстоящих событий, быстрый переход к расписанию.
- Лента объявлений кафедры с поддержкой закреплённых записей и тегами.
- Горизонтальная карусель событий с индикатором заполненности мест.

Между разделами приложения можно переключаться как через нижнюю навигацию, так и свайпами влево и вправо.

## Расписание

![Расписание](screenshots/timetable.png)

Расписание загружается с сервера по идентификатору группы студента или преподавателя, который извлекается из профиля автоматически после входа.

- Переключение между чётной и нечётной неделями через пилюлю-переключатель.
- Навигация по дням недели через чипы с датами.
- Цветовая маркировка типа занятия: лекция, практическое занятие, лабораторная работа.
- Статус пары в реальном времени: «Идёт», «Начнётся через N минут», «Закончилась».
- Поддержка ЭИОС-пар: вместо аудитории отображается ссылка на курс.
- Поиск расписания произвольной группы или преподавателя.
- Обновление по свайпу вниз.

## Профиль

![Профиль](screenshots/profile.png)

Карточка профиля показывает имя, роль и аватар пользователя. По нажатию открывается шторка с подробными данными.

Для студента отображаются: группа, подгруппа, поток, номер зачётной книжки, институт, дата рождения.

Для преподавателя: должность, учёная степень, кафедра, институт, теги научных интересов.

На экране профиля можно редактировать контактные данные (телефон, email, Telegram), биографию (для преподавателей), настройки темы, языка интерфейса и push-уведомлений. Аватар выбирается из галереи устройства.

## Посещаемость

![Посещаемость](screenshots/attendance.png)

Преподаватель создаёт сессию посещаемости на текущую пару. Студенты сканируют QR-код и получают отметку. Преподаватель видит список студентов в реальном времени и может вручную скорректировать статусы. По окончании пары сессия закрывается.

## Управление

Раздел доступен преподавателям и администраторам.

![Управление](screenshots/management.png)

- Публикация объявлений с таргетингом по конкретным группам или потокам.
- Создание событий кафедры с указанием аудитории и времени проведения.
- Работа с дипломными работами: создание, редактирование, просмотр статусов.
- Просмотр списков студентов по группам.

## Архитектура

Проект построен по принципам Clean Architecture. Каждая фича независима и содержит три слоя: данные, домен и представление.

```
lib/
├── main.dart
└── src/
    ├── app/
    │   ├── dependency_injection/      # GetIt — регистрация всех зависимостей
    │   └── screens/                   # Навигация, HomeScreen, AuthWrapper
    ├── core/
    │   ├── auth/                      # AuthBloc, токены, интерцептор авторизации
    │   ├── error/                     # AppException, ExceptionHandler, типы ошибок
    │   ├── request/                   # Два Dio-клиента: публичный и авторизованный
    │   ├── theme/                     # AppTheme, AppColors, расширения темы
    │   ├── localization/              # Локализация (ru / en)
    │   └── widgets/                   # Переиспользуемые виджеты: UserAvatar, DetailSheet
    └── feature/
        ├── announcements/             # Объявления кафедры
        ├── attendance/                # Посещаемость и QR-сессии
        ├── chat/                      # Чат и сообщения
        ├── department/                # Сотрудники кафедры
        ├── events/                    # События кафедры
        ├── management/                # Управление (для преподавателей)
        ├── profile/                   # Профиль пользователя
        ├── qr/                        # QR-сканирование
        ├── settings/                  # Настройки темы и языка
        └── timetable/                 # Расписание занятий
```

Структура каждой фичи:

```
feature/example/
├── data/
│   ├── data_source/       # Remote (Dio) и Local (SecureStorage / SharedPreferences)
│   ├── dto/               # DTO — точная копия ответа сервера (freezed + json_serializable)
│   ├── mapper/            # Преобразование DTO в доменную модель
│   └── repository/        # Реализация репозитория
├── domain/
│   ├── entity/            # Доменная модель (freezed)
│   ├── repository/        # Интерфейс репозитория
│   └── use_case/          # Use cases
└── presentation/
    ├── bloc/              # BLoC: события, состояния, freezed
    ├── screens/           # Экраны
    └── widgets/           # Виджеты экрана
```

Поток данных: `DataSource → Repository → UseCase → Bloc → Widget`. Виджеты только отображают данные из состояния блока и отправляют события. Вся бизнес-логика сосредоточена в use cases и маппере.

DTO хранит поля в типах, которые сервер фактически возвращает (часто `String` вместо `int`). Маппер приводит их к удобным для UI типам и добавляет синтетические поля, которых на сервере ещё нет.

## Запуск

Создать файл `.env` в корне проекта:

```env
API_BASE_URL=https://your.api.host/api/v1
```

Установить зависимости и сгенерировать freezed-код:

```bash
flutter pub get
dart run build_runner build --delete-conflicting-outputs
```

Запустить приложение:

```bash
flutter run
```
